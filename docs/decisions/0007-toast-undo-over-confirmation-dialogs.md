# ADR 0007: 파괴적 동작에는 재확인 다이얼로그 대신 토스트 undo를 쓴다

- **Date**: 2026-04-19
- **Status**: Accepted
- **Deciders**: 본인

## Context

paynote은 개인 가계부 도구로, 사용자가 **하루에 수십 번 삭제·편집·복제**를 할 수 있다 (특히 매달 루틴·과거 수정 시). 전통적인 "정말 삭제하시겠습니까?" 다이얼로그는:

- 실수 방지 효과보다 **확인 피로**가 크다 — 사용자는 읽지 않고 클릭.
- 인터랙션 마찰(클릭 2회 + 초점 이동)이 매 동작마다 발생.
- 모바일에서 다이얼로그는 더 큰 방해 요소.

동시에, 데이터 모델에는 이미 **soft delete 원칙**이 있다 (`archivedAt` 필드 + architecture.md). hard delete 하지 않기로 되어 있으므로 복구가 기술적으로 가능.

## Decision

**모든 파괴적 동작**(Item 삭제, Account 아카이브, Template 삭제, 지난 달 복제로 인한 덮어쓰기 등)은 다음 패턴을 따른다:

1. 즉시 실행 (`archivedAt = now()` 또는 해당 변화 적용)
2. 화면 하단에 **토스트**를 5초 노출: `"삭제됨  [되돌리기]"`
3. 사용자가 "되돌리기" 클릭 시: `archivedAt = null` 등으로 복구
4. 토스트가 사라지면 상태는 고정 (archivedAt은 남지만 UI에서는 제외)

**재확인 다이얼로그(모달)는 사용하지 않는다.** 대신 필요한 경우 **인라인 배너**로 사전 정보 제공:
- 예: Account 아카이브 시 그 통장을 참조하는 항목 수를 폼에 배너로 표시 → 사용자가 아카이브 버튼을 누르면 바로 실행 + 토스트.

### 구현 규약

- 토스트 라이브러리: shadcn/ui의 `sonner` (단일 큐, 모바일 친화).
- 토스트 상태는 URL이나 DB에 반영하지 않는다 — 클라이언트 휘발성.
- "되돌리기" 액션은 `revalidatePath`를 다시 호출해 서버 상태 동기화.
- 서버 액션의 응답 포맷: `{ ok, undoToken }` — undoToken은 최근 archive의 id, "되돌리기"가 이 id로 restore 호출.

## Alternatives considered

- **재확인 다이얼로그** (`window.confirm` 또는 모달): Context 참조. 거절.
- **hard delete + 복구 불가**: 실수의 비용 너무 큼. 이미 soft delete 정책 있으므로 안 맞음.
- **휴지통 페이지 (Trash)**: 복구는 가능하나 UX가 무겁고, 가계부 사용자가 "휴지통"을 주기적으로 관리하는 건 비현실적. 토스트로 **즉시 복구**가 더 낫다.
- **키보드 `Cmd+Z` 전역 undo 스택**: 구현 복잡 (어떤 상태까지 undo 가능? 여러 계층의 상태 기록?). 토스트 undo는 단일 액션 스코프라 단순.

## Consequences

### 얻은 것

- **마찰 없는 삭제** — 한 번의 클릭으로 실행, 실수는 5초 내 복구.
- 모바일·데스크톱에서 동일한 UX (다이얼로그는 모바일에서 특히 거슬림).
- soft delete 정책과 자연스럽게 결합.
- 접근성 — 토스트는 ARIA live region으로 스크린 리더에 알림 가능.

### 포기한 것

- 5초 이내 인식 못한 삭제는 사용자 인지상 "영구 삭제"처럼 느껴짐. 복구는 DB 수동 쿼리 필요 (archivedAt를 null로 업데이트).
- Phase 2에서 "휴지통" 페이지를 요구하는 니즈가 생길 수 있음 → 그때 별도 화면 추가 (이 ADR 유지).

### 유지 비용

- 토스트 시스템이 한 곳에만 존재해야 함 (중첩 토스트 큐 버그 방지).
- "되돌리기"가 멱등적(idempotent)인지 테스트 필수.
- 한 화면에서 다중 삭제를 했을 때 토스트가 올바르게 스택 처리되는지 확인.
