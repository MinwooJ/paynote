# ADR 0001: 로컬 우선 Next.js + SQLite + Drizzle 스택

- **Date**: 2026-04-18
- **Status**: Accepted
- **Deciders**: 본인

## Context

paynote은 단일 사용자(본인)가 매달 가계 기록을 입력·조회하는 개인용 도구다. 요구사항은 다음과 같다:

- 입력이 쉬워야 한다 (웹 UI).
- 데이터는 본인 기기 안에 있어야 하며, 외부 서비스에 민감한 금융 정보를 올리는 것은 피하고 싶다.
- 배포·운영 오버헤드를 최소화하고 싶다 (서버 호스팅, DB 운영, 인증 등 불필요).
- 그러나 장기적으로 모바일/다기기 접근 수요가 생기면 클라우드로 이관할 수 있는 여지를 남겨두고 싶다.

## Decision

**Next.js 15 (App Router) + TypeScript strict + SQLite (better-sqlite3) + Drizzle ORM**을 로컬 전용으로 사용한다.

- 실행: `pnpm dev`로 로컬호스트에서 서빙, 브라우저로 접속.
- 데이터: 프로젝트 폴더 내 `paynote.db` (SQLite 파일).
- 스키마: Drizzle로 정의하되 **SQLite·Postgres 양쪽에서 작동하는 공통 타입만 사용** (JSON, 복잡한 배열 타입 회피).

## Alternatives considered

- **Electron / Tauri 데스크톱 앱**: 설치·빌드·배포 복잡도 상승. 본인이 주로 쓰는 디바이스가 Mac 하나라 웹앱 로컬 서빙으로 충분.
- **Google Sheets 또는 Notion 계속 사용**: 현재 메모장과 동일한 문제(합계 오차, 통장별 배분 계산의 반복) 재발. 도메인 모델이 유연하지 않음.
- **Supabase/Firebase 즉시 사용 (클라우드 우선)**: 민감한 금융 데이터를 외부로 내보내는 부담 + 운영 비용. 단일 사용자에게는 과함.
- **순수 정적 HTML + localStorage**: 백업·이관·쿼리 난이도. 월별 통계 집계를 직접 JS로 짜야 함.
- **아무것도 안 하기**: 메모 방식 오차가 실측으로 발견됨 (2025-09 메모 -337,000원 오차). 계속 두면 누적됨.

## Consequences

### 얻은 것

- 서버리스·호스팅리스 운영. 껐다 켜는 비용 없음.
- 민감 데이터가 로컬 디스크 안에 머무름.
- Drizzle의 타입 안전성으로 스키마 변경 시 컴파일 에러로 포착.
- Postgres 호환 스키마 유지 → 미래의 클라우드 이관 경로 열림.

### 포기한 것

- 모바일/타기기 실시간 접근. (PC를 켜야 씀.)
- 자동 클라우드 백업. → `paynote.db` 파일을 수동 백업해야 함 (iCloud/Google Drive 동기화 폴더 배치 권장).
- 여러 기기 간 동시 편집. (단일 사용자라 필요 없음.)

### 유지 비용

- 스키마 변경 시 SQLite·Postgres 호환성 체크 필요 (Drizzle 타입 제약 준수).
- `paynote.db` 파일 백업을 사용자가 책임져야 함.
